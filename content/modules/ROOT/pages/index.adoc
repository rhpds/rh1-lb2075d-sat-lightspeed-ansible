= Red Hat Satellite: Automated CVE Remediation with Lightspeed and AAP
:imagesdir: ../assets/images

Security teams face a relentless pace of CVE disclosures.
Finding which hosts are vulnerable, which packages need updating, and pushing those fixes fleet-wide — without missing a single host — is hard to do reliably by hand.

This lab shows you how Red Hat Satellite, the on-premises *Red Hat Lightspeed Vulnerability* service, and *Ansible Automation Platform (AAP)* work together to close that gap automatically.
Satellite detects which CVEs affect which managed hosts.
A Satellite webhook forwards job events to *Event-Driven Ansible (EDA)*.
EDA fires an AAP Job Template that finds every affected host and installs the correct package fixes — including hosts that never fired an event of their own.

You configure this pipeline from scratch, trigger it with a single remote execution job, and confirm that both managed hosts come out patched.

== Learning Objectives

By the end of this lab, you will be able to:

* Explore CVE data in the Red Hat Lightspeed Vulnerability dashboard hosted on-premises by Red Hat Satellite
* Configure a Satellite webhook to send events to AAP's Event-Driven Ansible Event Stream on remote execution job success
* Automate fleet-wide CVE remediation by wiring an EDA rulebook to launch an AAP Job Template that installs fixes across all affected hosts
* Verify end-to-end closed-loop remediation by confirming that vulnerable packages are patched on both managed hosts after a single triggering event

== Lab Environment

Your environment consists of four pre-provisioned virtual machines:

* *satellite.lab* — Red Hat Satellite server with the on-premises Lightspeed Vulnerability service enabled and CVE data pre-synced
* *aap1.lab* — Ansible Automation Platform with EDA pre-configured to receive webhooks and remediation playbooks already in place
* *rhel1.lab* and *rhel2.lab* — RHEL hosts registered to Satellite with deliberately vulnerable packages installed

You access the environment through six browser tabs: the Satellite Web UI, the AAP Web UI, and terminal sessions for each of the four hosts.

All CVE data is served by Satellite itself.
No host inventory or package list leaves the lab network.
The same configuration works in a disconnected environment.
